# Генератор атласов шрифтов

Строит атлас signed distance field и метрики к нему — то, чем движок заменяет
`code/rd-common/tr_font.cpp` и его битмапные атласы.

## Откуда берутся глифы

**Главный источник — родные шрифты игры.** `ergoec`, `anewhope`, `aurabesh`,
`arialnb` — это и есть то, как выглядят JK2 и JKA, и подменять их системным
шрифтом нельзя: получится резкий текст не той гарнитурой, что не улучшение.
Поэтому на вход идёт `.fontdat` (метрики) и `.tga` рядом с ним (атлас глифов),
а поле расстояний считается из покрытия этого битмапа.

```
python3 tools/fontgen/msdf.py \
    --fontdat  base/fonts/ergoec.fontdat \
    --fontdat-image base/fonts/ergoec.tga \
    --out-image ergoec_sdf.png --out-meta ergoec_sdf.json
```

**TrueType — только для того, чего в игре нет.** Шипнутые шрифты — это 256
глифов, кириллицы в них нет ни одной. Для таких кодовых точек можно собрать
поле из контуров, и тогда оно многоканальное (MSDF) со всеми углами на месте:

```
python3 tools/fontgen/msdf.py --font /path/to/face.ttf \
    --charset 0x400-0x45f \
    --out-image cyr_sdf.png --out-meta cyr_sdf.json
```

Из битмапа поле одноканальное, размноженное в три канала. Это не спрятанный
костыль: многоканальность требует знать, где проходят рёбра контура, а битмап
говорит только сколько чернил в тексе. Шейдер берёт медиану трёх каналов в
обоих случаях, а медиана трёх одинаковых чисел — это само число, так что
шейдер один. Теряется резкость углов, которой в исходном битмапе и не было:
эти глифы растеризованы в 16–32 пикселя, углы у них уже мягкие.

## Что сохраняется дословно

`horizAdvance`, `horizOffset`, `baseline`, `mPointSize`, `mHeight`,
`mAscender`, `mDescender` уходят в метаданные без изменений. Это не аккуратность
ради аккуратности: перенос строк в игре складывает `horizAdvance` и больше
ничего — `CG_ScrollText` идёт по строке, накапливая ширину, пока не перевалит за
`SCREEN_WIDTH - 16`. Сдвинется хоть один advance — вступительный текст перед
первой катсценой поедет по строкам иначе. `--range` добавляет поле вокруг
глифа, и padding сложен в `xoff`/`baseline`/`gw`/`gh`, а не в advance.

## Проверка

```
python3 tools/fontgen/selftest.py      # входит в стадию tests
```

Синтезирует `.fontdat` из любого TrueType на машине, гоняет через генератор и
проверяет три вещи: что атлас — поле, а не плоский лист (первая версия меняла
местами два преобразования расстояний и молча выдавала однородно-серый атлас);
что ни один advance не сдвинулся; и что поле, отрисованное шейдерной
арифметикой один к одному, даёт ровно тот же силуэт, что исходный битмап.

Посмотреть глазами:

```
python3 tools/fontgen/preview.py --meta atlas.json --image atlas.png \
    --scales 1,2,4 --out preview.png
```

`preview.py` считает ровно то, что будет считать шейдер
(`clamp((median(rgb) - 0.5) * screenPxRange + 0.5, 0, 1)`), и ругается, если
`range` на выбранном размере меньше полутора пикселей — ниже этого сглаживать
уже нечем и края встанут жёсткими.
