# `jkx_smoke.bsp` — карта, которая не карта

151 байт, на один байт короче заголовка `dheader_t`. Она здесь не для того,
чтобы загрузиться, а для того, чтобы **не** загрузиться правильным образом.

`SV_Map_f` проверяет только существование файла (`sv_ccmds.cpp:66`), и лишь
потом зовёт `SV_SpawnServer`. А тот первым делом делает `Hunk_Clear` — то есть
освобождает `TAG_HUNKALLOC` и обнуляет весь `tr` рендерера. И только после
этого доходит до `CM_LoadMap`, который на такой файл честно ругается.

Получается дешёвый способ открыть то самое окно, в котором рендерер пуст:
движок сносит своё состояние, спотыкается о карту, возвращается в меню — и
дальше рисует кадры уже поверх обнулённого `tr`. Ровно там жили три падения
на первой загрузке карты на настоящем железе (`docs/Backlog.md`, §13).

Файл заодно нашёл и то, ради чего он не задумывался: `CM_LoadMap` копировал
заголовок целиком из буфера длиной с файл, не проверив, что файл хотя бы такой
длины. Восемь байт за границей кучи на любой обрезанной карте.

**Чего этот файл пока не проверяет:** регистрацию моделей внутри окна. Она
происходит в `SV_InitGameProgs`, до которого отсюда не добраться — для этого
нужна настоящая карта и те девять файлов конфигурации, о которых §10.
