# Фаза 2: сборка рендерера в нашем дереве

Цель фазы 2 — чтобы `code/rd-vulkan` собирался здесь, а не внутри чекаута
MP-форка. Пока это не сделано, «сколько осталось» было оценкой. Теперь есть
цель сборки, и остаток печатает компилятор.

```sh
cmake -B build -G Ninja -DBuildSPRdVulkan=ON
cmake --build build --target rdsp-vulkan_x86_64 -- -k 0
```

`BuildSPRdVulkan` по умолчанию **OFF**: цель не собирается намеренно, и CI
остаётся зелёным. Включать при работе над портом.

---

## 1. Как менялось число ошибок

| Состояние | Ошибок | Падающих TU (из 76) |
|---|---|---|
| Цель заведена | 60 | 60 |
| `ghoul2_shared.h` перестал включаться преждевременно | 11 357 | 59 |
| `q_shared.h` включён перед `qfiles.h` | **180** | **34** |

Средняя строка — не опечатка. MP-шный `ghoul2_shared.h` лежит в `codemp/ghoul2`
и включается явно; SP-шный лежит в `code/game`, и `q_shared.h` подтягивает его
сам под guard-ом `GHOUL2_SHARED_H_INC`. Включение его напрямую, раньше этого
контекста, стоило одиннадцати тысяч ошибок: файл не самодостаточен.

Последняя строка — тоже одна строка кода. MP-шный `qfiles.h` включает
`q_shared.h` сам, SP-шный не включает ничего и рассчитывает быть вторым.
Ровно так же устроен `rd-vanilla/tr_local.h`. Все 11 177 разошедшихся ошибок
были одним и тем же `'vec3_t' does not name a type`.

Мораль на остаток фазы: **сначала порядок и расположение заголовков, потом
семантика**. Разница между «11 тысяч ошибок» и «180» — это две строки, и обе
про то, где лежит файл, а не про то, что в нём написано.

## 2. Что осталось: 180 ошибок, 34 файла

### 2.1 Интерфейс `refimport_t` — 94 ошибки, основная работа

Рендерер зовёт через `ri.` то, чего в SP-шном refimport нет:

| Не существует в SP | Вызовов |
|---|---|
| `ri.Hunk_Alloc` | 29 |
| `ri.Hunk_FreeTempMemory` | 23 |
| `ri.Hunk_AllocateTempMemory` | 21 |
| `ri.VK_IsMinimized` | 6 |
| `ri.CM_GetCachedMapDiskImage` | 4 |
| `ri.CM_BoxTrace` | 3 |
| `ri.CM_SetUsingCache`, `ri.CM_PointLeafnum`, `ri.CM_LeafCluster` | по 2 |
| `ri.Z_Malloc`, `ri.VK_createSurfaceImpl` | по 1 |

Плюс 41 вхождение `h_low` и `ha_pref` — MP-шный hunk API с предпочтением
размещения, которого в SP нет вовсе.

Это и есть пункт 2.2 роадмапа. Причём монолит его решает сам собой: если
рендерер перестаёт быть DLL, `ri.Hunk_Alloc` становится просто `Hunk_Alloc`, а
таблица refimport исчезает целиком. Делать 2.2 до того, как чинить эти 94
вызова по одному, — почти наверняка дешевле.

### 2.2 Ghoul2 — 10 файлов

`ghoul2/g2_local.h` в SP **нет вообще**: внутренний API Ghoul2 у MP лежит в
отдельном заголовке, у SP — иначе. Это пункт 2.3 роадмапа (вынести `G2_*`,
10 930 строк, из рендерера в движок), и до него эти файлы не соберутся.

### 2.3 Мелочь, но именно её забывают

| Что | Где | Комментарий |
|---|---|---|
| `qcommon/disablewarnings.h` | 1 файл | у SP нет, у MP есть |
| `qcommon/GenericParser2.h` | 1 файл | у SP другое расположение |
| `LS_LSNONE` | 5 | lightstyle enum, разошёлся |
| `TAG_TEMP_IMAGE`, `TAG_GRIDMESH` | по 1 | теги Z_Malloc, MP-only |
| `Square` | 2 | хелпер, у SP под другим именем |
| `refEntity_t::data` | 2 | union из MP-раскладки |
| `VK_PRESENT_MODE_FIFO_LATEST_READY_EXT` | 1 | **не про SP**: наш FetchContent приколот к Vulkan-Headers v1.3.290, а константа новее |
| `-Werror=write-strings` | 4 | строковые литералы в `char *`, наш же гейт |

## 3. Порядок

1. **2.2, монолит.** Убирает 94 ошибки не по одной, а целым классом, вместе с
   таблицей refimport. Заодно исчезает граница DLL и весь класс дефектов
   вокруг выгрузки модуля.
2. **2.3, вынести Ghoul2.** Разблокирует 10 файлов.
3. Мелочь из §2.3 — по списку.
4. Поднять пин Vulkan-Headers.
5. Удалить `tr_sp_compat.h`, харнесс и `check_sp_shape.sh`: когда цель
   собирается здесь, вторая форма сборки перестаёт быть нужна.
